Heximal Slides is built on @heximal/templates, @heximal/components, and @radica/ui. Click any of the 10 element buttons to jump directly to its deep-dive slide.

Every slide starts with <h-slide> and a child <template>. Even with static HTML, you get Shadow DOM style isolation and hash routing out of the box.

Layouts keep slide markup concise: simple slides use a single <template>, while structured slides pass named <template name="..."> blocks directly inside <h-slide> without an extra outer wrapper.

Expressions are evaluated inside a signal effect, so any change to a signal—whether from a button click, input event, or deck navigation—immediately updates only the affected DOM bindings.

Because builds just increment the signal-backed step variable from 0 to stepCount, you can drive any animation, class toggle, or conditional template from step.

<h-slide-deck> is the presentation document container. It can be used standalone or wrapped inside <h-slide-viewer> or <h-slide-presenter>.

Click the "Overview" button in the toolbar right now to show the live thumbnail grid of all slides in the deck.

Just like Jinja templates, if a sub-template doesn't include an explicit <template name="super"> call, it implicitly renders the super template with its overridden named blocks.
